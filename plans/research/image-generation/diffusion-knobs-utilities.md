## A) Diffusion models with sampler knobs

Open-weights hosts expose the sampler; closed frontier models hide it.

| Knob              | fal `flux-2/klein/4b/base`         | fal `flux-2` (dev) | fal `qwen-image` | fal `hunyuan-image/v3` | Replicate `flux-dev`                     | BFL `/v1/flux-2-flex`             | BFL `/v1/flux-2-pro` | Together `/images/generations` | gpt-image-2                          | Nano Banana (Gemini)    |
| ----------------- | ---------------------------------- | ------------------ | ---------------- | ---------------------- | ---------------------------------------- | --------------------------------- | -------------------- | ------------------------------ | ------------------------------------ | ----------------------- |
| steps             | `num_inference_steps` 4-50, def 28 | 4-50, def 28       | 2-250, def 30    | 1-50, def 28           | 1-50, def 28                             | `steps` 1-50, def 50              | none                 | `steps` def 20                 | none                                 | none                    |
| guidance          | `guidance_scale` 0-20, def 5       | 0-20, def 2.5      | 0-20, def 2.5    | 1-20, def 7.5          | `guidance` 0-10, def 3                   | `guidance` 1.5-10, def 5          | none                 | `guidance_scale` def 3.5       | none                                 | none                    |
| seed              | yes (echoed in output)             | yes                | yes              | yes                    | yes                                      | yes                               | yes                  | yes                            | **no**                               | **no**                  |
| negative_prompt   | yes                                | no                 | yes              | yes                    | no                                       | no                                | no                   | yes                            | no                                   | no                      |
| img2img strength  | n/a                                | n/a                | n/a              | n/a                    | `prompt_strength` 0-1, def 0.8 + `image` | `input_image`..`_8` (no strength) | same                 | `image_url`                    | input images, no strength            | ref images, no strength |

| output_format     | jpeg/png/webp                      | same               | jpeg/png         | jpeg/png               | webp def + `output_quality` 0-100        | jpeg/png/webp                     | same                 | jpeg def                       | png/jpeg/webp + `output_compression` | `mime_type`             |
| speed             | `acceleration` none/regular/high   | same               | same             | none                   | `go_fast` (fp8) + `megapixels`           | none                              | none                 | none                           | `quality` low/med/high               | `thinking_level`        |
| count             | `num_images` 1-4                   | 1-4                | 1-4              | 1-4                    | `num_outputs` 1-4                        | 1                                 | 1                    | `n`                            | `n` 1-10                             | none                    |
| scheduler/sampler | none                               | none               | none             | none                   | none                                     | none                              | none                 | none                           | none                                 | none                    |

Findings:

- **No hosted API in this set exposes a scheduler/sampler name.** That knob lives only in local stacks (diffusers, ComfyUI). Hosts fix the sampler and expose `steps` + `guidance`.
- **Seed on closed models:** gpt-image-2 has no `seed` in the generate reference or guide; Gemini image docs have no seed either. Only a third-party blog claims seed "reduces variance" for gpt-image-2 (UNVERIFIED, not in OpenAI docs). BFL pro/max drop `steps`/`guidance` but keep `seed`; only `flex` and `klein` expose the sampler. So "seed" is near-universal on open and mid-tier closed APIs but absent from the two frontier closed models.
- Response shapes agree on `images[] {url|b64, width, height, content_type}` plus echoed `seed` and (fal) `has_nsfw_concepts[]`, `timings`. BFL is async: `{id, polling_url, cost}` then `get_result`.

Concrete schemas:

- fal FLUX.2 klein: `{prompt, negative_prompt, image_size: preset|{width,height}, num_inference_steps, guidance_scale, seed, num_images, acceleration, enable_safety_checker, output_format, sync_mode}` (fal-ai/flux-2/klein/4b/base OpenAPI, https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=fal-ai/flux-2/klein/4b/base)
- Replicate flux-dev: `{prompt, aspect_ratio, image?, prompt_strength, num_outputs, num_inference_steps, guidance, seed, output_format, output_quality, disable_safety_checker, go_fast, megapixels}` -> `List[Path]` (https://raw.githubusercontent.com/replicate/cog-flux/main/predict.py)
- BFL flux-2-pro: `POST /v1/flux-2-pro {prompt, input_image..input_image_8, width, height, seed, safety_tolerance, output_format, disable_pup, webhook_url, webhook_secret}` (https://docs.bfl.ml/api-reference/models/generate-or-edit-an-image-with-flux2-[pro].md)

| Together               | Canny/Depth/Redux no longer in serverless model list                                                                                | absorbed                                                                                                                                                               |

Verdict: explicit control-type + strength is **niche and receding**. The 2026 mainstream shape is "prompt + N reference images" with no control type or strength field (FLUX.2 `input_image_1..8`, Seedream v4 `image_urls` up to 10, Nano Banana up to 14 refs, gpt-image-2 multi-input). Only Stability keeps a classic ControlNet-style surface; Recraft/Ideogram keep _style_ refs as a typed field.

Verdict: "generate with a LoRA reference" is **common on every open-weights host** (fal, Replicate, Together, BFL) and absent on closed models. Shape is either `loras[{path, scale}]` (array, up to 3) or `finetune_id + finetune_strength` (single). Training/CRUD is separate and can be ignored.

| Upscale              | Stability `upscale/fast` (no params), `/conservative` (`prompt`, `creativity` 0-0.35), `/creative` (async job id)                                                            | image           | bytes or `b64_json`                                                           |
| Upscale              | Recraft `crispUpscale`, `creativeUpscale`: `image_url` only                                                                                                                  | image           | url/b64                                                                       |
| BG removal           | fal `birefnet/v2`: `image_url`, `model`, `operating_resolution`, `refine_foreground`, `output_mask`, `mask_only`                                                             | image           | `{image, mask_image?}`                                                        |
| BG removal           | Recraft `removeBackground`, Stability `edit/remove-background`, fal `ideogram/remove-background`                                                                             | image           | png                                                                           |
| Outpaint             | Stability `edit/outpaint` `{left,right,up,down}`; BFL `/v1/flux-tools/outpainting-v1`, `/v1/flux-pro-1.0-expand`                                                             | image + margins | image                                                                         |
| Erase / deblur / VTO | BFL `/v1/flux-tools/erase-v1`, `deblur-v1`, `vto-v1/v2`; Stability `edit/erase` (mask), `search-and-replace`, `search-and-recolor`, `replace-background-and-relight` (async) | image (+mask)   | image                                                                         |
| Vectorize            | Recraft `vectorize`, fal `recraft/vectorize`: `image_url` only                                                                                                               | raster          | `image/svg+xml`                                                               |
| Layer split          | fal `bytedance/seedream/v5/pro/layerize`: `image_url`, optional `prompt`, `image_size`                                                                                       | image           | `layers[{image, z_index, bounding_box, name, description}]` (base + up to 16) |

SDK coverage: Vercel AI SDK `generateImage` covers only `{prompt, n, size, aspectRatio, seed, providerOptions}` and (v6) reference images; docs say nothing about upscale, background removal, masks, or SVG (https://ai-sdk.dev/docs/ai-sdk-core/image-generation). LangChain has no first-party utility wrapper; the community ModelsLab tool bundles upscale/remove-background (UNVERIFIED depth). So in 2026 these are **separate endpoints, not folded into generic image-generation SDKs**. They are a distinct capability: single image in, single image (or image + mask, or layers) out, no prompt required, no seed/steps.

## Summary for library design

- Sampler knobs (`steps`, `guidance`, `negative_prompt`, `loras`, `acceleration`, safety toggle) are provider-typed and open-weights only; `seed` and `num_images`/`n` are shared by everything except gpt-image-2 and Gemini.
- Control-type + strength is legacy; typed "reference images" is the unified 2026 shape.
- LoRA-at-generate is an open-weights standard (`loras[{path, scale}]`), worth a provider-typed field, not a common one.
- Utilities (upscale, bg removal, vectorize, layerize) and SVG/alpha/layer outputs are distinct capabilities with image-in shapes and non-raster or multi-file outputs; no generic AI SDK unifies them.
