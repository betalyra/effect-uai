## A) Native multimodal LLM image output (chat turn emits images)

Not natively emitting images: **GPT-5.x chat models** (text-only output; images only via the tool). **Grok chat** likewise only via the tool or `/v1/images`. **Qwen**: Qwen3-Omni outputs text+audio, Qwen-Image/Qwen-Image-3.0 is a standalone diffusion model. BAGEL / Janus / OmniGen are research checkpoints with no first-party interleaved API (UNVERIFIED whether any hosted API exposes interleaved output for them). Muse Spark 1.1 itself is text-out; images go through the separate tool.

**Design pattern that emerges**: every provider except Gemini-legacy models images as a _tool call whose result is an image_, chained by an opaque server-side id. Gemini models it as an _output part/step of the turn_. Both fit an existing LanguageModel abstraction: an `image` content part in the assistant turn (Gemini) plus a provider-defined tool whose result carries bytes (OpenAI/xAI/Meta). The only genuinely new state is the continuation handle (`previous_response_id` / `previous_interaction_id` / `image_generation_call.id`), which is conversation-level, not image-level.

**What other SDKs do**: Vercel AI SDK keeps it inside `generateText`/`streamText`: Gemini images surface in `result.files` (`GeneratedFile` with `mediaType`) and as `'file'` stream parts; OpenAI images surface as `staticToolResults` for `toolName === 'image_generation'` with `output.result` b64. No separate abstraction. LangChain (Python) returns Gemini images as `image_url` content blocks (`data:image/...;base64,`) on the `AIMessage` when `response_modalities=[Modality.IMAGE]` is set. Conclusion: a separate `ImageGenerator` service is still right for `/v1/images`-style endpoints, but chat-turn images need no new service, only an `image` TurnEvent/part and passthrough for the provider tool.

Known 2026 caveats: Gemini 3.1 Flash Image multi-turn at 2K/4K 404'd on both APIs until a fix on Aug 11 2026; `imageConfig.imageSize` and `aspect_ratio` were reported ignored on preview builds. Vercel's `imageConfig` had only `aspectRatio` until an open request added `imageSize`.

## B) Real-time / streaming diffusion over WebSocket

**Status: niche, largely frozen at the 2023-24 LCM/SDXL-Turbo generation.**

| Provider     | Transport                                                                                                                                                                                                                | Config                                                                                                                                                                                                                                                                                                                                                 | Models                                                                                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **fal**      | `wss://fal.run/{model_id}/realtime`; **msgpack** by default (JSON via `encodeMessage`/`decodeMessage`); browser auth via proxy or short-lived JWT `tokenProvider` + `tokenExpirationSeconds`                             | JS `fal.realtime.connect(model, {connectionKey, throttleInterval (ms, e.g. 128), onResult, onError})`; Python `fal_client.realtime()` context manager with `send()`/`recv()`; payload `{prompt, sync_mode, image_url}`; results as base64 when `sync_mode:true`; best at 512x512. Queue-only knobs (`priority`, `webhook_url`, retries) have no effect | Documented list is only `fast-lcm-diffusion` and `fast-turbo-diffusion`; `fast-lightning-sdxl` model page also advertises a realtime mode. No FLUX realtime endpoint found (UNVERIFIED that any newer model exposes it) |
| **Krea**     | Realtime exists as an app feature and as an open-source WebSocket server for the Krea Realtime 14B _video_ model (non-commercial). Public API (`https://api.krea.ai`) is async jobs + poll/webhook, no realtime endpoint | n/a                                                                                                                                                                                                                                                                                                                                                    | n/a                                                                                                                                                                                                                     |
| **Together** | No realtime image WebSocket found; WebSocket is used for audio                                                                                                                                                           | n/a                                                                                                                                                                                                                                                                                                                                                    | n/a                                                                                                                                                                                                                     |

Shape difference vs plain text-to-image: a long-lived connection, client-side throttling, prompt-as-a-stream (each send supersedes the last), binary frames, and no job ids.

## C) Batch APIs for image generation

**Status: mainstream at OpenAI and Google; absent at fal/Replicate/Krea (they do async queues, not discounted batches).**

| Provider                   | Shape                                                                                                                                                               | Image support                                                                                                                                                                                                                                    | Price / SLA                                                                                                                                                                        |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OpenAI Batch**           | JSONL lines `{custom_id, method:"POST", url, body}`; upload with `purpose:"batch"`, create batch with `input_file_id` + `endpoint`, poll, download `output_file_id` | Endpoints include `/v1/images/generations`, `/v1/images/edits`, `/v1/responses` (so the image tool path too, UNVERIFIED), `/v1/videos`. gpt-image-2 model page lists `v1/batch: Supported`. Multipart uploads not allowed; pass asset references | 50% off, 24h window, separate rate-limit pool                                                                                                                                      |
| **Gemini Batch**           | `batches.create(model, src=inline requests                                                                                                                          | uploaded JSONL, config.display_name)`; poll `JOB_STATE_*`; results in `dest.inlined_responses`or`dest.file_name`; results kept 6 weeks. Inline ≤20MB, file ≤2GB                                                                                  | Doc example uses `responseModalities:["TEXT","IMAGE"]` with `gemini-3-pro-image-preview`; image returned as `inlineData`. `gemini-3.1-flash-image` capability table: Batch API Yes | 50% off, 24h target |
| **fal / Replicate / Krea** | Async job APIs only: fal `queue.submit/status/result` + webhooks; Replicate predictions + signed webhooks (`webhook_events_filter`); Krea jobs + webhooks           | Yes, but same price as sync                                                                                                                                                                                                                      | No batch discount (Together has a JSONL batch API at ~50% off, but for LLMs only; image support UNVERIFIED)                                                                        |
