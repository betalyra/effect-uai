# Subagent report: image generation schemas on model routers and OpenAI-compatible hosts (2026-09-04)

Raw research report. Summarised in
[../image-generation.md](../image-generation.md).

## Baseline: OpenAI Images API

`POST /v1/images/generations` (JSON) and `POST /v1/images/edits` (multipart; JSON `images[{image_url|file_id}]` also accepted on some gateways). Request: `prompt, model, n, size, quality, background, output_format, output_compression, moderation, response_format, style, user, stream, partial_images` (+ `image`, `mask`, `input_fidelity` for edits). Response `{created, data:[{b64_json|url, revised_prompt}], usage:{input_tokens, output_tokens, total_tokens, input_tokens_details}}`. SSE: `image_generation.partial_image|completed`, `image_edit.partial_image|completed`. Source: https://developers.openai.com/api/docs/guides/image-generation

## 1. OpenRouter

- **Current**: `POST /api/v1/images` (own schema, not OpenAI). Request: `model, prompt, n(1-10), size, resolution("512"|"1K"|"2K"|"4K"), aspect_ratio, quality(auto|low|medium|high), output_format(png|jpeg|webp|svg), background, output_compression, seed, stream, user, provider{...}, input_references[]` where items are `{type:"image_url", image_url:{url}}` (max 16, URL or data URL). **No `response_format`, no `mask`, no `url` output**: response is `{created, data:[{b64_json, media_type}], usage:{prompt_tokens, completion_tokens, total_tokens, cost, cost_details}}`. SSE events: `image_generation.partial_image {partial_image_index, b64_json}`, `image_generation.text_chunk` (svg), `image_generation.completed {b64_json, created, usage, media_type}`, `error`, `[DONE]`. Capability discovery: `GET /api/v1/images/models` (enum/range/boolean descriptors per param). Sources: https://openrouter.ai/docs/guides/overview/multimodal/image-generation, https://openrouter.ai/docs/api/api-reference/images/generate-an-image.md, https://openrouter.ai/openapi.json
- **Chat path**: still in the OpenAPI: `modalities: ["text","image","audio"]`, `image_config` (free-form provider map, e.g. `aspect_ratio`, `quality`), and assistant `images: [{image_url:{url}}]`. The image guide no longer documents it; the launch blog says existing models stay supported but "new image models will be added exclusively to the dedicated Image API" and GPT Image via chat lacks params and may cost more. So: legacy, not removed. Source: https://openrouter.ai/blog/announcements/image-api/
- **OpenAI paths**: `/api/v1/images/generations` returns **401** without a key (real route) while `/images/edits`, `/images/variations` return 404, and `/images/generations` is absent from their OpenAPI. Treat as an undocumented alias of `/images`; its exact shape is **UNVERIFIED**. No edits path.

## 2. Requesty (`https://router.requesty.ai/v1`)

OpenAPI at https://docs.requesty.ai/api-reference/openapi.json. Paths: `/v1/images/generations`, `/v1/images/edits`, both return `ImageGenerationResponse {created, data:[{url, b64_json}]}` (no `usage`, no `revised_prompt` in schema).

- Generations request: `model, prompt, n, size(1024x1024|1536x1024|1024x1536), quality(auto|high|medium|low), response_format(url|b64_json, default url), background, output_format(png|jpeg|webp)`. No `stream`, `partial_images`, `moderation`, `output_compression`, `style`.
- Edits: multipart `image[]` (binary, up to 16), `mask` (binary), `size(auto|...)`, `quality`; or JSON `images:[{file_id|image_url}]`, `mask: ImageReference`. Docs page also mentions `input_fidelity, output_compression, response_format` for edits but the spec omits them (UNVERIFIED).
- Models: `azure/openai/gpt-image-1`, `gpt-image-1.5` on Images API; Gemini image models (`vertex/google/gemini-2.5-flash-image-preview`, `gemini-3.1-flash-image-preview`, `gemini-3-pro-image-preview`) only via chat completions with `image_config{aspect_ratio,image_size}` returning `message.images[]`. No FLUX/Seedream listed. Verdict: OpenAI subset, not verbatim. Source: https://docs.requesty.ai/features/image-generation

## 3. Vercel AI Gateway (`https://ai-gateway.vercel.sh/v1`)

Both REST and SDK. Image-only models (`openai/gpt-image-2`, `bfl/flux-*`, `spacexai/grok-imagine-image`) use OpenAI-compatible `/v1/images/generations` (`model, prompt, n, response_format`, plus non-OpenAI `providerOptions{<provider>:{...}}` in the body) and `/v1/images/edits` (multipart `image` (up to 16), `mask`, or JSON `images:[{image_url}]`; `file_id` unsupported; streaming partial edits unsupported; mask warning for unsupporting models). Response `data[].b64_json`. Multimodal LLMs (Gemini image, GPT-5) use `/v1/chat/completions` returning `message.images[{type:"image_url", image_url:{url:"data:..."}}]`, streamed as `delta.images`. AI SDK `generateImage` (ImageModelV3: `prompt, n, size, aspectRatio, seed, files, mask, providerOptions`). Source: https://vercel.com/docs/ai-gateway/modalities/image-generation/openai, https://vercel.com/docs/ai-gateway/modalities/image-generation/ai-sdk

## 4. Other "compatible" endpoints

- **xAI**: `/v1/images/generations` and `/v1/images/edits` (JSON). Request: `model, prompt, n, response_format(url|b64_json), aspect_ratio(enum), resolution("1k"|"2k"), quality(low|medium|auto per guide), storage_options, user`; edits take `image:{type:"image_url", url}` or `images[]` (≤5 in guide). Reference lists `size, mask, stream` as unsupported. Response `data[{url|b64_json, mime_type, file_output, storage_error}], usage` (reference omits `created`/`revised_prompt`; the guide shows them: conflicting, UNVERIFIED). Source: https://docs.x.ai/developers/rest-api-reference/inference/images
- **Meta Model API** (`https://api.meta.ai/v1`): `/v1/images/generations`, `/v1/images/edits`, "mirror the OpenAI Images API"; `model:"muse-image-1.0", prompt, n, size, response_format, output_format, image|images[] (URL or file_id), user, stream` with `image_generation.completed`/`image_edit.completed` SSE. Response `{created, data[{b64_json|url}], output_format, usage}`. Mask, quality, background not documented (UNVERIFIED). Source: https://dev.meta.ai/docs/image-generation
- **Together**: `/v1/images/generations` only (`/images/edits` → 404). Request is its own: `prompt, model, n, steps, width, height, seed, negative_prompt, guidance_scale, response_format("base64"|"url"), output_format(jpeg|png), image_url, reference_images[], image_loras, disable_safety_checker`. Response `{id, model, object:"list", data[{index, url|b64_json}]}`: no `created`, no `size`/`quality`. Source: https://docs.together.ai/reference/post-images-generations
- **Fireworks**: no OpenAI images path (404); async workflow endpoint `/inference/v1/workflows/accounts/fireworks/models/{model}` with `prompt, input_image, aspect_ratio, seed, output_format, safety_tolerance` → `request_id`. Source: https://docs.fireworks.ai/api-reference/generate-or-edit-image-using-flux-kontext
- **Groq**: no image generation (404).
- **LiteLLM proxy**: `/v1/images/generations`, `/v1/images/edits`, `/v1/images/variations` (beta), OpenAI shape; unknown params passed through as provider kwargs; response `{created, data[{url, b64_json, revised_prompt}], usage}`. Source: https://docs.litellm.ai/docs/image_generation
- **Portkey**: `/v1/images/generations` (OpenAI signature incl. `moderation, output_format, output_compression, background, stream, partial_images` for gpt-image-1); `/v1/images/edits` supported subset, `mask` not supported yet. Source: https://portkey.ai/docs/product/ai-gateway/multimodal-capabilities/image-generation
- **Cloudflare AI Gateway**: `/compat` supports chat/completions only; images via universal `/ai/run` per-model schema. Source: https://developers.cloudflare.com/ai-gateway/usage/rest-api/
- **Azure**: `/openai/v1/images/generations?api-version=preview` and `/openai/deployments/{d}/images/edits?api-version=...`; OpenAI shape but `response_format` unsupported (always `b64_json`); `stream`, `partial_images`, `mask`, `input_fidelity` supported. Source: https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/dall-e

## 5. Is there a formal standard?

No. The only maintained cross-provider contracts are SDK-internal: Vercel `ImageModelV3CallOptions` (`prompt, n, size "WxH", aspectRatio "W:H", seed, files[], mask, providerOptions`) and LiteLLM's OpenAI-param list with kwargs passthrough. OpenRouter explicitly built a _new_ normalized schema. OpenAI's Images API is the de-facto wire baseline (Requesty, Vercel, Meta, xAI, Azure, LiteLLM, Portkey copy its paths and envelope), but far less faithfully than Chat Completions: field enums, `response_format`, masks, and streaming diverge per host. Source: https://raw.githubusercontent.com/vercel/ai/main/packages/provider/src/image-model/v3/image-model-v3-call-options.ts

## (b) Verdict

One OpenAI-Images codec + base URL covers **Requesty, Vercel Gateway, Meta, Azure, LiteLLM, Portkey** for generate and multi-image edit, if the codec (1) makes every request field optional, (2) decodes `data[]` items as `{url?, b64_json?, media_type?/mime_type?, revised_prompt?}` with `created`/`usage` optional, and (3) supports both multipart `image[]` and JSON `images:[{image_url}]` for edits. **xAI** fits only with `aspect_ratio`/`resolution` extras and no `size`/`mask`. It breaks for **OpenRouter** (different path, `input_references`, own SSE names, no edits path, no `url`), **Together** (`width/height/steps`, no `created`), **Fireworks/Cloudflare** (non-OpenAI). Practical design: one OpenAI-Images codec with a provider-extras escape hatch (`providerOptions`/passthrough), plus a separate OpenRouter Images codec; keep the chat-completions `modalities`+`images[]` path in the existing Chat codec since OpenRouter, Requesty, and Vercel all still use it for Gemini-style multimodal models.
