## 2. Per-provider notes

### 2.1 xAI Grok Voice Agent API

- Launched 2025-12-17; positioned as OpenAI Realtime compatible and shipped with an official LiveKit plugin (`xai.realtime.RealtimeModel`).
- Endpoint: `wss://api.x.ai/v1/realtime?model=grok-voice-latest`; auth `Authorization: Bearer {XAI_API_KEY}`.
- Models: `grok-voice-latest` (alias), `grok-voice-think-fast-2.0` (flagship), `grok-voice-think-fast-1.0` (deprecated).
- Client events: `session.update`, `input_audio_buffer.append` (base64 JSON, or binary frames when `audio.input.transport: "binary"`), `input_audio_buffer.commit`, `input_audio_buffer.clear`, `conversation.item.create` (messages, `function_call_output`, xAI-only `force_message` for scripted TTS without inference), `conversation.item.truncate`, `response.create`.
- Server events: `response.output_audio.delta`, `response.done`, `response.function_call_arguments.done`, `input_audio_buffer.speech_started`, `conversation.created`, and `conversation.item.input_audio_transcription.updated` (cumulative transcript; xAI's replacement for OpenAI's `.delta`).
- Not supported vs OpenAI: `conversation.item.retrieve`, `conversation.item.done`, transcription failure events.
- Session extensions: `reasoning.effort` ("high" | "none"), `audio.input.transcription.language_hint` and `keyterms`, `audio.output.speed` 0.7 to 1.5, `replace` pronunciation map, `resumption.enabled` plus `?conversation_id=` (server caches turns 30 min), tools of type `function`, `file_search`, `web_search`, `x_search`, `mcp`.
- Audio: `audio/pcm` at 8000, 16000, 22050, 24000 (default), 32000, 44100, 48000 Hz; `audio/pcmu`, `audio/pcma`, `audio/opus`; configured per direction.
- Turn detection: `server_vad` (threshold, silence, prefix padding, idle timeout) or `null` for manual turns.
- Browser auth: ephemeral token as WebSocket subprotocol `xai-client-secret.{token}`.
- Pricing (docs.x.ai/developers/models): 2.0 at $0.08/min audio plus $0.004 text input as printed; 1.0 at $0.05/min. STT $0.10/hr REST, $0.20/hr streaming; TTS $15/M chars.
- Quality: #1 Big Bench Audio at launch (92.3%). Artificial Analysis: Think Fast 2.0 High 97% reasoning, Elo 908, 0.70 s time to first audio; Think Fast 1.0 leads tau-Voice agentic at 52.1%.
- Compliance claims: SOC 2 Type II, HIPAA-eligible, GDPR; audio not stored.

### 2.2 Amazon Nova 2 Sonic

- Model `amazon.nova-2-sonic-v1:0` (launched 2025-12-02, 1M context, 64K max output); predecessor `amazon.nova-sonic-v1:0`.
- Transport: `InvokeModelWithBidirectionalStream` on `https://bedrock-runtime.{region}.amazonaws.com`, an HTTP/2 AWS event stream (Smithy framing), not a WebSocket. JS needs `@aws-sdk/client-bedrock-runtime` with `NodeHttp2Handler`.
- Auth: SigV4 (AWS credentials) or a long-term Bedrock API key via `AWS_BEARER_TOKEN_BEDROCK`. No browser credential.
- Regions: us-east-1, us-west-2, eu-north-1, ap-northeast-1. In-region only, no cross-region inference.
- Input events (ordered): `sessionStart` (inferenceConfiguration maxTokens/topP/temperature, `turnDetectionConfiguration.endpointingSensitivity`), `promptStart` (promptName, `audioOutputConfiguration` audio/lpcm 24000 Hz 16-bit mono voiceId, `textOutputConfiguration`, toolConfiguration), `contentStart` type TEXT role SYSTEM + `textInput` + `contentEnd`, `contentStart` type AUDIO role USER (audio/lpcm 16000 Hz base64) + repeated `audioInput` + `contentEnd`, `promptEnd`, `sessionEnd`.
- Output events: `contentStart` (role, `additionalModelFields.generationStage` SPECULATIVE or FINAL), `textOutput` (role USER for ASR, ASSISTANT for the reply; barge-in emits the literal `{ "interrupted" : true }`), `audioOutput` (base64), `toolUse` (toolName, toolUseId, content), `contentEnd` with type TOOL, `completionEnd`.
- Tool results: client sends `contentStart` type TOOL + `toolResult` + `contentEnd`; v2 guide advertises asynchronous tool handling (assistant keeps speaking while tools run).
- Text input mid-conversation: supported (cross-modal audio and text in one session).
- Session limit: 8 minutes per connection; AWS samples ship a session continuation pattern.
- Languages: English (US, UK, IN, AU), French, Italian, German, Spanish, Portuguese, Hindi; polyglot voices; automatic language switching.
- Pricing: model card defers to the Bedrock pricing page, which did not render; press and aggregators quote $3/M speech input, $12/M speech output, $0.33/$2.75 text (UNVERIFIED).
- Quality: Artificial Analysis 88% reasoning, Elo 917, 1.14 s. LiveKit plugin is Python only.

### 2.3 Microsoft: Azure Voice Live, Azure OpenAI Realtime, MAI

- Voice Live is GA (no preview banner on the overview; Q&A threads date GA to 2025-10-01, UNVERIFIED). WebRTC mode is public preview.
- Endpoint: `wss://{resource}.services.ai.azure.com/voice-live/realtime?api-version=2026-04-10&model={model}` (older resources: `.cognitiveservices.azure.com`). Auth: Entra bearer with scope `https://ai.azure.com/.default`, or `api-key` header or query param.
- Protocol: Azure OpenAI Realtime events, plus additive Azure fields on `session.update`.
- Turn detection: `server_vad`, `semantic_vad` (gpt-realtime only), `azure_semantic_vad`, `azure_semantic_vad_multilingual` (all models) with `remove_filler_words`, `interrupt_response`, `auto_truncate`, `languages`.
- Input processing: `input_audio_sampling_rate` 16000 or 24000; `input_audio_noise_reduction.type: azure_deep_noise_suppression`; `input_audio_echo_cancellation.type: server_echo_cancellation` with Live-Reference AEC (stereo pcm16, api-version 2026-07-15).
- Transcription: `input_audio_transcription.model` in `azure-speech`, `mai-transcribe` (preview), `whisper-1`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize`.
- Voice: object `{ name, type: azure-standard | azure-custom | azure-realtime-native, temperature, rate }`; MAI-Voice-2-Flash voices are `azure-standard` names like `en-US-Harper:MAI-Voice-2-Flash`.
- Extra outputs: `output_audio_timestamp_types: ["word"]` giving `response.audio_timestamp.delta/done`; `animation.outputs: ["viseme_id"]` giving `response.animation_viseme.delta/done`; `avatar` with `session.avatar.connect` / `session.avatar.connecting`.
- Native S2S models: `gpt-realtime-1.5`, `gpt-realtime`, `gpt-realtime-mini` (plus `-datazone` variants), Azure's own `azure-realtime` (api-version 2026-01-01-preview or later, 34 `azure-realtime-native` voices across en, es, fr, de, it, pt, hi, ja, ko, zh, th), `phi4-mm-realtime` (preview).

## 3. Is there an OpenAI-Realtime-compatible wire standard?

Yes, in practice, with two dialects and per-vendor extensions.

Verbatim or superset implementers of the OpenAI event family (`session.update`, `input_audio_buffer.append`, `input_audio_buffer.commit`, `conversation.item.create`, `response.create`; `response.*.delta`, `response.done`, `input_audio_buffer.speech_started/stopped`, `conversation.item.input_audio_transcription.completed`):

- Azure OpenAI Realtime: identical to OpenAI GA.
- Azure Voice Live: Azure OpenAI Realtime events plus additive `azure_*` session fields and extra timestamp, viseme, avatar and `rtc.call.*` events. Same codec with an extension schema.
- xAI Grok Voice: GA dialect (`response.output_audio.delta`, `audio.input.transport`), extensions from 2.1, a few OpenAI events missing, `.updated` cumulative transcript event.
- Inworld Realtime: GA dialect, extended with model routing fields.
- Alibaba Qwen-Omni-Realtime and StepFun: the 2024-12 preview dialect (`response.audio.delta`, `modalities`, string `input_audio_format`) rather than GA (`session.type: realtime`, `audio.output.format` object, `response.output_audio.delta`).
- vLLM-omni (self-hosted Qwen3-Omni): preview dialect.

Not compatible: Gemini Live (BidiGenerateContent), Amazon Nova Sonic (own event names over HTTP/2), ElevenLabs, Hume, Deepgram, Ultravox, Speechmatics, AssemblyAI, Kyutai, PersonaPlex, Doubao.

Consequence for effect-uai: one `OpenAiRealtime` codec parameterised by

- dialect: `"ga" | "preview"` (event names and session shape),
- an endpoint and auth adapter (bearer header; Azure api-key or Entra; xAI ephemeral subprotocol; Inworld Basic),
- an open extension slot on `session.update` (Schema with additional properties)
  covers OpenAI, Azure OpenAI, Azure Voice Live, xAI, Inworld, Qwen and StepFun. LiveKit Agents already treats these as one family (openai plugin plus thin `xai.realtime` and Azure wrappers) and keeps bespoke plugins for Nova Sonic, Gemini Live, Ultravox, PersonaPlex and Phonic, which mirrors this split.

## 4. Agent platforms vs model APIs

A model API lets the caller pass instructions, tools and voice at connect time and executes tools on the client. An agent platform stores prompt, tools and voice as a server-side resource created out of band. effect-uai does not manage resources.

Model APIs (in scope):

- xAI Grok Voice, Amazon Nova 2 Sonic, Azure OpenAI Realtime, Qwen-Omni-Realtime, StepFun: native S2S, inline config.
- Azure Voice Live in model mode (the `agent_id` Foundry Agent mode is a platform feature to ignore).
- Hume EVI via inline `session_settings`.
- Deepgram Voice Agent and Inworld Realtime: inline config, but cascades.

Agent platforms (out of scope):

- ElevenLabs Agents (`agent_id` required, signed URLs bound to an agent).
- Speechmatics Flow (`template_id`), Cartesia Line (hosted code runtime), Retell, Vapi.
- Ultravox sits in between: prompt and tools are inline on `POST /api/calls`, but it is a REST-created call resource with a server-only WebSocket, a half cascade, and its own binary framing; treat as platform-like.

## 5. Ranking and recommendation

Ranking by importance for a model library (quality per Artificial Analysis S2S index and Big Bench Audio, native S2S, mindshare, protocol reuse):

1. OpenAI gpt-realtime family (separate report).
2. Gemini Live (separate report).
3. xAI Grok Voice Think Fast 2.0: top-tier reasoning and agentic scores, cheapest fast native S2S, OpenAI protocol.
4. Amazon Nova 2 Sonic: the only hyperscaler-native S2S with enterprise pull; distinct protocol.
5. Azure Voice Live: gpt-realtime plus `azure-realtime` under one OpenAI-shaped socket; enterprise Azure demand.
6. Qwen-Omni-Realtime: leaderboard quality, very cheap, OpenAI preview dialect.
7. Hume EVI: distinct expressive S2S, proprietary protocol.
8. StepFun: strong scores, small mindshare outside China.
9. Inworld: cascade, but existing package and OpenAI protocol.
10. Deepgram Voice Agent: popular cascade.
    Everything else is platform, cascade-only, self-host, or unreachable.

Launch set:

- xAI Grok Voice Agent API. Near-verbatim OpenAI GA dialect, so mostly an endpoint and auth adapter on the OpenAI codec; best public benchmarks; ephemeral tokens for browsers. New package `@effect-uai/xai` (no xAI package exists today).
- Azure Voice Live API. Same codec with an Azure extension schema (`azure_semantic_vad`, noise suppression, echo cancellation, Azure voices); reaches gpt-realtime, gpt-realtime-mini and Azure's own `azure-realtime`; covers Azure OpenAI Realtime for free. New package `@effect-uai/azure`, or an Azure endpoint config on a shared OpenAI-compatible realtime layer (openai-compatible chat precedent).
- Amazon Nova 2 Sonic. The one major native S2S with a genuinely different transport (HTTP/2 event stream, SigV4) and event vocabulary; enterprise AWS shops will ask for it. New package `@effect-uai/bedrock`; the 8-minute reconnect must be built into the session abstraction.

Second wave:

- Hume EVI: differentiated expressive S2S with inline session settings; small proprietary protocol (about 20 message types); new package.
- Qwen-Omni-Realtime and StepFun: cheap once the codec has a `preview` dialect flag; cost-sensitive and Asia-region users; new packages; need Singapore or China accounts for testing.
- Inworld Realtime: existing `@effect-uai/inworld` and OpenAI dialect make it small; cascade, so only on demand.
- Deepgram Voice Agent: widely used cascade with client-side function calling; proprietary Settings protocol; new package.

Skip:

- ElevenLabs Agents, Cartesia Line, Speechmatics Flow, Retell, Vapi: agent platforms with server-side resources; out of scope.
- Ultravox, AssemblyAI Voice Agent: cascade or half cascade with bespoke transport; no quality or mindshare advantage over the launch set.
- Mistral, Anthropic, Meta, MiniMax, Fish Audio, Gladia, Groq, Fireworks, Together, OpenRouter, Sesame: no S2S model API today.
- Kyutai Moshi/Unmute, NVIDIA PersonaPlex: self-host only; revisit if a hosted endpoint appears.
- Zhipu GLM-Realtime, ByteDance Doubao: unverifiable docs and China-only access.
- Deepslate, Phonic: watch list; re-check when public protocol docs and pricing exist.

Design notes that fall out of the survey:

- Every native S2S API supports server VAD, barge-in, client-executed tools, text injection and transcript events, so those belong in the common `RealtimeSession` request.
- Noise suppression, echo cancellation, semantic VAD eagerness, filler-word removal, avatar and viseme outputs, reasoning effort, resumption: provider-typed knobs, not common fields.
- Session length is the sharpest non-uniformity: 8 min (Nova), 30 min (Hume), 60 min (Azure OpenAI), 120 min (Qwen), unstated (xAI, with a 30 min resumption cache). The abstraction needs a reconnect-with-context hook rather than a uniform limit.
- Audio: pcm16 at 16 or 24 kHz mono covers every launch-set provider; xAI and ElevenLabs add g711 and opus; Hume outputs 48 kHz WAV.
- Browser auth: only xAI, Azure OpenAI (ephemeral key), ElevenLabs (signed URL) and Hume (access token) document a client credential; Nova Sonic and Voice Live WebSocket need a server relay.
