Shared pattern, with the canonical reference lines in the OpenAI file:

- `Socket.makeWebSocket(url, { closeCodeIsError: (code) => code !== 1000 && code !== 1001 && code !== 1005 })` (`openai/realtimeStt.ts:194-198`). The same literal appears in all seven files (`mistral:211-215`, `elevenlabs/realtimeStt:264-269`, `elevenlabs/realtimeTts:136-138`, `inworld/realtimeStt:209-213`, `inworld/realtimeTts:156-160`, `cdp:115-119`). Effect's `makeWebSocket` accepts `closeCodeIsError`, `openTimeout` (default 10 s) and `protocols` (`node_modules/.pnpm/effect@4.0.0-rc.111/node_modules/effect/src/unstable/socket/Socket.ts:592-595`).
- `Queue.bounded<Event, Cause.Done>(64)` (`openai:199`), reader fiber `socket.runString(handler).pipe(Effect.ensuring(Queue.end(queue)), Effect.forkScoped)` (`openai:212-214`), return `Stream.fromQueue(queue)` (`openai:216`). The `Queue.end` vs `Queue.shutdown` comment is repeated in every adapter (`openai:209-211`, `elevenlabs/realtimeTts:153-156`, `inworld/realtimeTts:175-177`).
- Writer fiber: `Effect.gen(handshake; Stream.runForEach(input, write); end-frame).pipe(Effect.ignore, Effect.forkScoped)` (`openai:204-207`, `mistral:226-236`, `elevenlabs/realtimeTts:145-151`, `inworld/realtimeStt:221-226`, `inworld/realtimeTts:167-173`). Mistral adds `Effect.tapError(logWarning)` before `Effect.ignore` (`mistral:231-234`); the others swallow write failures silently.
- Whole body wrapped in `Stream.unwrap(Effect.gen(...))` (`openai:184-218`). There is no `Stream.scoped` in the adapters: the `Effect.forkScoped` fibers require `Scope`, and the top-level helper in core also just `Stream.unwrap`s (`packages/core/src/transcriber/Transcriber.ts:123-129`). The Scope is supplied by whoever runs the stream (`Stream.runForEach` / `Stream.runDrain` provide one; `recipes/voice-loop/app.ts:183-185` wraps in `Effect.scoped`). Service docs claim `Stream.scoped` semantics (`Transcriber.ts:53-57`) but the mechanism is fork-scoped fibers, not an explicit `Stream.scoped`.
- Auth header injection: `authedWsConstructor(cfg): Socket.WebSocketConstructor["Service"] = (url) => new WSWebSocket(url, undefined, { headers }) as unknown as globalThis.WebSocket` (`openai:168-176`, `mistral:195-200`, `inworld/wsAuth.ts:16-21`). Provided per-call with `Effect.provideService(Socket.WebSocketConstructor, ...)` so the public `R` stays free of the constructor. ElevenLabs instead relies on `Socket.layerWebSocketConstructorGlobal` (`Socket.ts:580-582`) because auth rides on a query param, so it works in browsers, Node 22+, Bun, Deno (`elevenlabs/realtimeStt.ts:41-43`, `:231-235`).
- Frame decode: `Schema.Union([Schema.Struct({ type: Schema.Literal(...) , ...}), ...])` + `Schema.decodeUnknownEffect` (`openai:94-115`), then `Match.type<typeof ServerEvent.Type>().pipe(Match.when({ type: ... }), Match.exhaustive)` (`openai:117-148`) or `Match.value(decoded).pipe(Match.when(...), Match.orElse(...))` (`mistral:147-168`). Inworld's wire is non-discriminated so it uses a permissive struct and if-chains (`inworld/realtimeStt.ts:142-178`).
- `JSONL.parseSafe(raw)` returns `Effect<unknown>` that succeeds with `undefined` on parse failure (`packages/core/src/streaming/JSONL.ts:50-51`). Every handler does `parseSafe -> decode.pipe(Effect.option) -> map -> Queue.offer` and drops unknown frames silently (`openai:150-158`, `mistral:140-169`, `elevenlabs/realtimeStt:213-226`, `elevenlabs/realtimeTts:99-116`, `inworld/realtimeStt:180-188`, `inworld/realtimeTts:113-128`, `cdp:129-159`).
- Errors: pre-connect gating fails with `AiError.Unsupported` (`openai:33-52`, `mistral:66-75`, `elevenlabs/realtimeStt:23-39`, `inworld/realtimeStt:39-60`). Server `error` frames become in-band `TranscriptEvent { _tag: "error" }` (`openai:142-146`) or are just logged (`elevenlabs/realtimeTts:106-112`, `inworld/realtimeTts:120-123`). Socket transport failures (`SocketError`, including a 401 on upgrade) are never mapped to `AiError`: the reader fiber ends, `Queue.end` runs, and the stream completes cleanly with nothing emitted (`openai:212-214`); only Mistral logs a warning (`mistral:246-252`). CDP is the exception: it captures the close cause and fails every pending command with `CdpError { kind: "closed" }` (`cdp:161-177`).
- Binary frames: `socket.runString` decodes every frame as text (`Socket.ts:74-79`); `socket.run` gives `Uint8Array`, `runRaw` gives `Uint8Array | string` (`Socket.ts:66-86`). The writer accepts `Uint8Array | string | CloseEvent` (`Socket.ts:86-88`). `fromWebSocket` already normalises `Blob` frames (browser `WebSocket` default for binary) through `arrayBuffer()` and `ArrayBuffer` frames to `Uint8Array` before calling the handler (`Socket.ts:650-664`), so a Gemini Live adapter that receives JSON as binary frames in some runtimes can use `runRaw` and decode both shapes. No adapter today sends or receives binary WS frames; all audio is base64 inside JSON.
- Lifecycle, as every adapter implements it: (1) pre-connect gating and token fetch, (2) `makeWebSocket` (connects lazily on first `run*`/write), (3) fork writer, (4) fork reader with `Queue.end` in `ensuring`, (5) return `Stream.fromQueue`. Teardown is the consumer closing the Scope; nothing sends a WS close frame explicitly (the writer accepts a `CloseEvent`, unused at HEAD).
- CDP is the only request/response correlator: `Deferred` per pending id in a `HashMap` ref (`cdp:81-84`, `:145-158`), id-less messages go to a `PubSub` (`cdp:123`, `:135-143`). A realtime session that needs to await an ack (`session.updated`, `setupComplete`, `response.done`) can copy this shape.

Duplicated helpers a `core` WebSocket session helper could absorb (concrete, counted at HEAD):

1. `closeCodeIsError` predicate literal: 7 copies.
2. `Queue.bounded<A, Cause.Done>(64)` + `ensuring(Queue.end)` + `forkScoped` reader: 6 copies.
3. `handleServerMessage` = `parseSafe -> decodeUnknownEffect(...).pipe(Effect.option) -> map -> Queue.offer`: 6 copies with only the schema and mapper varying.
4. `authedWsConstructor` with the `ws` cast and the same explanatory comment: 3 copies (`openai:163-176`, `mistral:191-200`, `inworld/wsAuth.ts`).
5. `(cfg.baseUrl ?? DEFAULT).replace(/^http/, "ws")`: 6 copies (`openai:58`, `mistral:82`, `elevenlabs/realtimeStt:186`, `elevenlabs/realtimeTts:52`, `inworld/realtimeStt:67`, `inworld/realtimeTts:57`).
6. Writer fiber shape `handshake -> runForEach(write) -> end frame` + `Effect.ignore, Effect.forkScoped`: 6 copies.
7. Base64 audio decode into `AudioChunk` with a swallowed failure: `elevenlabs/realtimeTts.ts:87-97` and `inworld/codec.ts` `decodeAudioContent` (used at `inworld/realtimeTts.ts:126`).

The `onHalt` test: `packages/providers/mistral/src/onHalt.test.ts` is not a WS test. It drives `Mistral.streamTurn` (SSE) with a scripted `HttpClient` (`:8-19`) and guards that a truncated body without `finish_reason` (`:36-47`) and a mid-stream transport error (`:49-60`) never synthesize a `TurnComplete`, while a well-formed stream still completes (`:62-74`). The guarded code is `Mistral.ts:155-157` (`onHalt` fires on upstream failure and truncation, so it must not emit a completion). The same rule transfers to a realtime session: a socket close must not synthesize a turn or response boundary.

## 2. Domain types

`packages/core/src/domain/Audio.ts`

- `AudioFormat` (`:54-70`): `container | encoding | sampleRate (8000..48000 union) | bitRate? | channels?`. Reusable as-is. Both target providers fit: OpenAI Realtime is `raw/pcm_s16le/24000` (already mapped in `openai/realtimeStt.ts:40-52`), Gemini Live takes `raw/pcm_s16le/16000` in and emits `24000` out. The realtime session should declare both `inputFormat` and `outputFormat` with this type.
- `AudioChunk` (`:77-79`): `{ bytes }` only. Needs extension for realtime: output audio must be correlated to a response/item id so barge-in can truncate the right one (OpenAI `conversation.item.truncate` needs `item_id` + `audio_end_ms`). Suggest an `AudioDelta` event that wraps `AudioChunk` plus an id rather than widening `AudioChunk`.
- `AudioBlob` (`:85-89`) and `AudioSource` (`:38-41`): sync-only, unrelated to the session.

`packages/core/src/domain/Transcript.ts`

- `TranscriptEvent` (`:48-70`): `partial | final | speech-started | utterance-ended | audio-event | metadata | error`. Reusable for the user-side input transcription and VAD events (OpenAI `input_audio_buffer.speech_started`, Gemini `inputTranscription`). Needs an owner discriminator (user vs assistant) because both providers also emit the assistant's output transcription; either wrap it in a session event with a `role`, or add separate `OutputTranscriptDelta` events. `WordTimestamp` (`:11-18`) is unrelated (neither provider emits word timing on the realtime path).

`packages/core/src/domain/Turn.ts`

- `Turn` (`:25-30`): `{ items, usage, stop_reason }`. `StopReason` is a closed literal set (`Items.ts:238-247`); Gemini Live `turnComplete` has no stop reason, so an assembled `Turn` would need a synthesized `"stop"`.
- `TurnEvent` (`:65-84`): `TextDelta`, `ReasoningDelta`, `RefusalDelta`, `ToolCallStart`, `ToolCallArgsDelta`, `UsageUpdate`, `WebSearchCall`, `ImageOutput`, `CitationAdded`, `TurnComplete`. Reusable for the text and tool-call side of a response. Missing for duplex: `AudioDelta`, `Interrupted` (server-side VAD cut the response; OpenAI `response.cancelled`/`input_audio_buffer.speech_started`, Gemini `serverContent.interrupted`), `Truncated` (client-side truncate ack), `SessionExpiring` (Gemini `goAway.timeLeft`, OpenAI 60-minute limit), `InputTranscript` (user side), `SessionUpdated`/`SetupComplete` acks. `InteractionEvent = TurnEvent | ToolCallOutput` (`:94`) is the loop consumer shape; a realtime event union should be its own type, not an extension of `TurnEvent`, so the existing `Loop.onTurnComplete` contract (`Loop.ts:132-171`) stays untouched.

`packages/core/src/domain/Items.ts`

- `ToolCall` (`:152-160`): `{ type: "function_call", call_id, name, arguments: string }`. Matches OpenAI Realtime `response.function_call_arguments.done` (`call_id`, `name`, `arguments`) directly. Gemini Live `toolCall.functionCalls[]` carries `id`, `name`, `args` (object): adapter must `JSON.stringify(args)` and use `id` as `call_id`.
- `ToolCallOutput` (`:162-168`): `{ call_id, output: string }`. OpenAI takes it verbatim as a `conversation.item.create` item; Gemini `toolResponse.functionResponses[]` wants `{ id, name, response: object }`, so the adapter must `JSON.parse(output)` (and needs the tool `name`, which `ToolCallOutput` does not carry: keep a `call_id -> name` map in the session).
- `ContentBlock` (`:119`): `InputText | InputImage | OutputText | OutputImage | Refusal`. No audio block. A realtime session that wants to expose history as `HistoryItem`s needs `InputAudio`/`OutputAudio` blocks or must keep audio out of history (recommended for v1; OpenAI Realtime items reference audio by item id anyway).
- `providerData` (`:138`): opaque per-item slot; can carry OpenAI `item_id` / Gemini handles without touching the common shape.
- `Usage` (`:229-236`): all-optional; reusable for OpenAI `response.done.usage` and Gemini `usageMetadata`.

`packages/core/src/domain/Image.ts` and `Media.ts`

- `ImageSource = MediaSource<ImageMimeType>` with `bytes` / `base64` variants (`Image.ts:44-65`, `Media.ts:100-118`). Directly reusable as the payload of a `VideoFrame` input (Gemini Live `realtimeInput.video` is base64 JPEG frames; OpenAI has no video input yet). Only a new input variant `{ _tag: "video-frame", frame: ImageBase64Source | ImageBytesSource }` is needed; no new media type. `Media.ts:23-27` explicitly says streaming media lives per-modality, not in `Media.ts`.

## 3. Tool system

- Declaration: `Tool.make({ name, description, inputSchema, run })` (`packages/core/src/tool/Tool.ts:256-280`); `inputSchema` is Standard Schema + Standard JSON Schema (`:80-81`), Effect Schema via `fromEffectSchema` (`:88-91`). Four kinds: `LocalTool`, `ProviderTool`, `SignalTool`, `InteractionTool` (`:151-222`).
- Descriptors for the wire: `Tool.descriptorsOf(toolkit)` (`:434-437`) yields `{ name, description, inputSchema, strict? }`. Gemini's renderer wraps them as `functionDeclarations` and strips `$schema`/`$ref`/`additionalProperties`/`oneOf` (`packages/providers/google/src/codec.ts:434-475`). A Gemini Live `setup.tools` frame can reuse `toolDescriptorsToTools` if it is exported; OpenAI Realtime `session.tools` wants `{ type: "function", name, description, parameters }`, one field rename from the descriptor.
- Execution: `Toolkit.run(toolkit, calls)` returns `Stream<ToolEvent>` (`packages/core/src/tool/Toolkit.ts:386-395`); `Progress` events stream from a per-call queue (`:452-484`), `Output` carries `ToolResult` (`ToolEvent.ts:19-33`). `ToolResult.toToolCallOutput` produces the `ToolCallOutput` item (`ToolResult.ts:110-114`). `Tool.execute` is the single-shot variant (`Tool.ts:524-531`). `decodeArgs` handles JSON parse and validation errors as data (`Tool.ts:458-516`).
- Feedback into the loop: `Toolkit.continueWithResults(build)` taps outputs and emits `Loop.next(state)` at end (`Toolkit.ts:570-599`); `appendToolResults` appends `ToolCallOutput`s to history (`:529-532`).
- Approval: `Approval.fromQueue(predicate, verdicts)` is the WebSocket-shaped planner (per-call `Deferred`, router fiber, optional timeout) (`packages/core/src/tool/Approval.ts:74-160`); `fromMap` is the HTTP-shaped one (`:171-181`). `recipes/tool-call-approval/recipe.ts:166-228` drives the queue variant.
- Can a realtime session reuse `Toolkit`? Yes for declaration, descriptor rendering, decode, execution and approval: none of those depend on `Turn` or `Loop`. What changes is the feedback path: instead of `appendToolResults` + next `streamTurn`, the session must push `ToolCallOutput` back into the open socket (OpenAI: `conversation.item.create` + `response.create`; Gemini: `toolResponse` on the same stream). `continueWithResults` is loop-shaped and does not apply; `collectResults` (`Toolkit.ts:545-552`) does.
- What `Loop` assumes that duplex breaks (`packages/core/src/loop/Loop.ts`): a body is one pull-based `Stream<Step>` per iteration whose end is the iteration boundary (`:229-315`); `onTurnComplete` requires a terminal `TurnComplete` and fails `IncompleteTurn` otherwise (`:159-166`); state advances only through `Next`/`Stop` steps emitted by the body (`:286-298`). A duplex session has no caller-driven iteration boundary (input arrives while output streams), the server owns turn boundaries, interrupted responses never complete (`IncompleteTurn` would fire), and tool responses go back mid-turn rather than as the next iteration's history. `plans/websocket.md:58-63` and `:182-185` already noted this for Gemini's mid-turn `ToolCall`. The session should therefore be its own primitive (`Queue`/`Stream` in, `Stream` out), with `Loop` optionally layered on top by a recipe, not underneath.

## 4. Capability markers

- `packages/core/src/capabilities/Capabilities.ts` holds only the runtime warn-and-drop helpers `warnDropped`, `warnDroppedWhen`, `warnDroppedBlocks` (`:53-119`). Markers live next to the service they gate.
- Declaration: `export class SttStreaming extends Context.Service<SttStreaming, void>()("@betalyra/effect-uai/capability/SttStreaming") {}` (`packages/core/src/transcriber/Transcriber.ts:83-85`). Same shape for `TtsIncrementalText` and `MultiSpeakerTts` (`speech-synthesizer/SpeechSynthesizer.ts:151-153`, `:164-166`), `ImageStreaming` (`image-generator/ImageGenerator.ts:127`), `MusicInteractiveSession` (`music-generator/MusicGenerator.ts:89-91`), and the nine `Sandbox*` markers (`sandbox/Sandbox.ts:419-508`). Count at HEAD: 14 `Context.Service<X, void>` markers in core. No per-modifier `*Guarantee` markers exist yet (grep empty), despite `plans/capabilities-plan.md` planning them.
- Registration: `Layer.succeed(SttStreaming, undefined)` inside `Layer.mergeAll` (`packages/providers/openai/src/OpenAIRealtimeTranscriber.ts:44-57`, `elevenlabs/src/ElevenLabsSynthesizer.ts:255-256`). Registration is pessimistic: ship the marker only if every model the Layer routes to honors it (`plans/capabilities-plan.md:459-461`).
- Requirement: the top-level helper does `yield* Transcriber; yield* SttStreaming` inside `Stream.unwrap` so `R` gains the marker (`Transcriber.ts:110-130`); the service method itself does not require it (`:63-66`).
- `MusicInteractiveSession` is the closest precedent: a bidirectional `streamGenerationFrom(input: Stream<MusicSessionInput>, request) => Stream<MusicStreamEvent>` (`MusicGenerator.ts:48-72`) with a tagged input union `prompts | control` (`domain/Music.ts:83-93`) and tagged output union `audio | warning | filteredPrompt` (`Music.ts:156-158`). The marker is declared but no provider registers it at HEAD (no `Layer.succeed(MusicInteractiveSession` anywhere; `LyriaGenerator.ts:316-330` refers to a Lyria RealTime Layer that does not exist in `packages/providers/google/src`).
- The bar, quoted from `plans/capabilities.md:316-317`: "A per-modifier marker is justified when absence causes wrong behavior, not when it causes degraded behavior." Service-level markers (does this Layer expose this method at all) are described at `:185-193` and `:45-50`; the mechanism is stable, the per-modifier set is `@experimental` (`:28-33`). A `RealtimeSession` tag is a new service, so it needs no marker for the service itself; a marker is only warranted for a sub-capability whose silent absence breaks the caller (candidate: video input, which Gemini Live has and OpenAI Realtime WebSocket does not, matching the "LLM vision input: silent image drop" row at `:338`).
- Type tests for markers use `expectTypeOf` against `Effect.provide(layer)` (`packages/core/src/transcriber/Transcriber.test.ts:48-87`, `packages/providers/elevenlabs/src/ElevenLabsTranscriber.test.ts:44-63`).

## 6. recipe-kit and voice recipes

`packages/recipe-kit/src`

- `runtime.ts`: `RecipeServices = HttpClient | NodeServices | Socket.WebSocketConstructor` (`:32-36`); the platform layer merges `Socket.layerWebSocketConstructorGlobal` (`:79`), so a query-param-authenticated WS adapter needs no recipe wiring. `serveRecipe(main)` adds an `HttpServer` on `PORT` (`:137-138`, `:85-105`).
- `bundle.ts`: `bundleClient(entry)` bundles browser TS with rolldown to an ESM string (`:21-40`).
- `argv.ts`: `flagValue` (`:22-37`), `providerChoice` (`:85-87`), `choiceFlag` (`:61-77`), `intFlag` (`:94-98`).
- `recipes/_shared/model.ts`: per-capability registries of `Entry<L> = { layer: (apiKey, baseUrl) => L, apiKey: Effect<Redacted, ConfigError> }` (`:114-118`), keyed by provider name and resolved by `lookup` (`:121-133`) and `registry` (`:135`); env keys via `key("GOOGLE_API_KEY")` (`:106-112`). e.g. `streamingTranscriberLayer(spec)` returns `Layer<Transcriber | SttStreaming, ConfigError | UnknownProvider, SpeechDeps>` (`:413-417`). A `realtimeSessionLayer` picker with `openai` and `google` entries belongs here.

`recipes/voice-loop`

- `app.ts`: presets fix STT/LLM/TTS models and formats (`:72-102`); `/config` returns `{ micSampleRate, playbackSampleRate }` (`:234-244`); `wsHandler` bridges the browser socket with `Queue.unbounded<_, Cause.Done<void>>` in both directions and `HttpServerRequest.upgradeChannel` (`:171-210`); `toPlaybackS16le` converts f32le TTS output for the worklet (`:113-125`); worklets are bundled as separate entries (`:263-265`).
- `recipe.ts`: stop-word interrupt via `Fiber.interrupt(activeTurn)` (`:139-161`, `:266-277`), pacing sleep so the fiber lives while audio plays (`:224-235`), `Stream.share` to fan out STT events (`:263`). `streamOps.ts`: `settleBurst` resetting-window debounce (`:59-87`).
- `client/main.ts`: `pcmS16ToFloat32` (`:185-194`), `AudioContext` created at the playback rate from `/config` (`:244`), mic worklet with `sourceRate`/`targetRate` (`:258-268`), playback node (`:271-272`), WS demux text = status / binary = audio (`:289-301`), `clear` message to the playback worklet on `assistant-cancelled` (`:120-126`).
- `client/mic-worklet.ts`: averaging decimator to `targetRate`, s16le, 50 ms frames posted as `ArrayBuffer` (`:9-47`). `recipes/streaming-transcription/public/audio-worklet.js` is the same worklet as plain JS (`:1-15`).
- `client/playback-worklet.ts`: FIFO of `Float32Array` chunks with a 200 ms warmup hard-coded at 48 kHz (`:14`), `clear` drops everything buffered and re-arms warmup (`:33-38`). `recipes/streaming-synthesis/public/playback-worklet.js` and `client/main.ts:30` (`SAMPLE_RATE = 48000`) duplicate it.

Reusable verbatim for a realtime recipe: `mic-worklet.ts` (set `targetRate` 16000 for Gemini, 24000 for OpenAI), `pcmS16ToFloat32`, `playback-worklet.ts` and its `clear` message, the `/config` handshake, the `wsHandler` queue bridge, `bundleClient`, `serveRecipe`, the `client/index.html` shell (`recipes/voice-loop/client/index.html`, 83 lines) and the `worklet.d.ts` ambient types (`client/worklet.d.ts`).

Server-side pieces of voice-loop that a realtime recipe drops rather than reuses: stop-word detection and `Fiber.interrupt` (server VAD replaces it), `settleBurst` (server owns utterance boundaries), the pacing sleep (audio timing comes from the provider), the history `Ref` (the provider keeps conversation state on the socket). `f32leToS16le` (`app.ts:113-122`) stays relevant only if a provider emits float PCM; both targets emit s16le.

Missing on the browser side: (a) playback truncation by position for barge-in: the worklet only supports all-or-nothing `clear` and does not report how many samples it has played, which OpenAI's `conversation.item.truncate` (`audio_end_ms`) needs; (b) 24 kHz output: `WARMUP_SAMPLES` assumes 48 kHz, so at 24 kHz the warmup doubles to 400 ms (should derive from `sampleRate`); (c) no video frame capture (no `getUserMedia({ video })`, no canvas-to-JPEG sampler, no binary/base64 frame channel); (d) no text input channel in the voice-loop client (streaming-synthesis has one at `client/main.ts:102-120`); (e) no client-side echo cancellation settings (`getUserMedia({ audio: true })` at `main.ts:222`, worth `echoCancellation: true` when the assistant speaks through the same device).

## 8. Test conventions

- No adapter opens a socket in tests. The only WS-adjacent test is `packages/providers/elevenlabs/src/ElevenLabsTranscriber.test.ts`: runtime format guard that fails before the socket opens (`:25-42`) and `expectTypeOf` marker checks with the layer provided `FetchHttpClient.layer` + `Socket.layerWebSocketConstructorGlobal` (`:14-17`, `:44-63`). `openai/src/OpenAITranscriber.test.ts:13-30` checks the sync layer's `Unsupported` stub.
- Codec-level pure functions are exported for tests (`elevenlabs/realtimeStt.ts` `wireToEvent:135`, `buildWsUrl:180`, `inputFormatToSlug:30`; `inworld/realtimeStt.ts` `wireToEvent:142`; `openai/realtimeStt.ts` `wireToEvent:117`), but no `*.test.ts` covers the WS frame mappers today.
- Streaming HTTP paths are tested with a scripted `HttpClient.make` returning a `ReadableStream` body (`mistral/src/onHalt.test.ts:8-19`).
- No fake WebSocket server exists (grep for `WebSocketServer` in tests: none). `plans/websocket.md:309-312` decided to build a Vitest fake server with `ws` when needed. `Socket.WebSocketConstructor` is a `Context.Service` (`Socket.ts:569-571`), so a test can inject an in-memory fake `WebSocket` object without any server.
- Consumer-side tests use scripted mocks in `packages/core/src/testing/` (`MockTranscriber.layer` ships the marker `:83-108`, `layerSyncOnly` omits it `:114`); `recipes/voice-loop/recipe.test.ts` runs the pipeline against mocks for one utterance (`:86`), burst coalescing (`:125`) and growing history across utterances (`:154`); `recipes/voice-loop/streamOps.test.ts` covers `settleBurst`. A `MockRealtimeSession` in `core/testing` (scripted `RealtimeEvent` streams plus a recorder of pushed inputs) would follow this shape.
- Testing approach this suggests for the new capability: (1) pure frame-mapper tests per adapter (wire JSON in, `RealtimeEvent` out, and `RealtimeInput` in, wire JSON out) through the real `Schema` decode; (2) one in-memory fake `WebSocket` provided via `Socket.WebSocketConstructor` to test the session lifecycle (setup ack, interrupted response, tool call round trip, clean close, dirty close) without a server; (3) `expectTypeOf` for the tag and any marker; (4) recipe tests against `MockRealtimeSession`. No live-provider tests, matching the rest of the repo.
- Compile-time checks are inline `expectTypeOf` in real test files (`Transcriber.test.ts:48-87`).
