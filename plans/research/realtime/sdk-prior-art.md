## 1. OpenAI Agents SDK (JS and Python): RealtimeAgent / RealtimeSession

Shape: `RealtimeAgent` (instructions, tools, handoffs, guardrails) + `RealtimeSession` (stateful connection, event emitter) + a pluggable `RealtimeTransportLayer`. Only OpenAI's Realtime API is targeted; the abstraction is over transports, not providers.

JS `RealtimeSession` (from `realtimeSession.ts` and the class reference):

- Methods: `connect(options)`, `close()`, `sendMessage(content, otherEventData)`, `sendAudio(audio, { commit? })`, `interrupt()`, `mute(muted)`, `updateAgent(agent)`, `updateHistory(itemsOrFn)`, `approve(item)`, `reject(item)`. Properties: `transport`, `history`, `currentAgent`, `usage`.
- Options: `transport: 'webrtc' | 'websocket' | RealtimeTransportLayer`, `model`, `config: Partial<RealtimeSessionConfig>`, `outputGuardrails`, `outputGuardrailSettings.debounceTextLength`, `toolExecution`, `historyStoreAudio`, `automaticallyTriggerResponseForMcpToolCalls`, `toolErrorFormatter`, `tracingDisabled`, `groupId`, `traceMetadata`, `workflowName`, `context`.
- Session events (`session.on(...)`): `transport_event`, `history_updated(items)`, `history_added(item)`, `audio_start`, `audio(event)`, `audio_stopped`, `audio_interrupted`, `agent_start`, `agent_end(textOutput)`, `agent_tool_start`, `agent_tool_end`, `tool_approval_requested`, `agent_handoff(old, new)`, `guardrail_tripped(error, itemId)`, `mcp_tool_call_completed`, `mcp_tools_changed`, `error`.
- Transport events (from `openaiRealtimeBase.ts`): `connected`/`disconnected`, `error`, `item_update`, `item_deleted`, `turn_started`, `turn_done`, `usage_update`, `function_call`, `audio`, `audio_done`, `audio_transcript_delta`, `output_text_delta`, `mcp_tools_listed`, `mcp_approval_request`, `mcp_tool_call_completed`.
- Transports: `OpenAIRealtimeWebRTC` (browser), `OpenAIRealtimeWebSocket` (browser + Node), `OpenAIRealtimeSIP`, `TwilioRealtimeTransportLayer` (extensions). Browser auth via ephemeral client secret (`client_secrets`).
- Tool execution: client-side, automatic; `needsApproval()` on a tool pauses and emits `tool_approval_requested` until `approve()`/`reject()`. MCP tools go through `transport.sendMcpResponse`.
- Playback truncation ownership (`openaiRealtimeWebsocket.ts`): the WebSocket transport tracks `#currentItemId`, `#currentAudioContentIndex`, `_firstAudioTimestamp` (set on the first `response.output_audio.delta`), `_audioLengthMs` (accumulated as `byteLength / 24 / 2` for pcm16@24k). `interrupt()` sends `response.cancel`, then `conversation.item.truncate` with `audio_end_ms = clamp(Date.now() - _firstAudioTimestamp, 0, _audioLengthMs)`, then emits `audio_interrupted`. On `input_audio_buffer.speech_started` the transport calls `interrupt()` itself unless automatic response cancellation is disabled. So: wall clock since first delta, not real playout position; the app just stops its player.
- Twilio transport (`TwilioRealtimeTransport.ts`) does real playout tracking: sends Twilio `mark` events per audio chunk, keeps `#playbackItems` with `sentDurationMs` / `playedDurationMs`, computes `audioEndMs = min(sentDurationMs, playedDurationMs + 50)` and sends Twilio `clear` on interrupt.

Python `RealtimeSession` (guide): events `audio`, `audio_end`, `audio_interrupted`, `agent_start`, `agent_end`, `tool_start`, `tool_end`, `tool_approval_required`, `handoff`, `history_added`, `history_updated`, `guardrail_tripped`, `input_audio_timeout_triggered`, `error`, `raw_model_event`. Methods `send_message()`, `send_audio(bytes, commit=)`, `approve_tool_call()`, `reject_tool_call()`, `model.send_event()` for raw escape. `RealtimeRunner(model_settings=...)` carries `audio.input.format/transcription/turn_detection`, `audio.output.format/voice`; run config has `async_tool_calls`, `output_guardrails`, `tool_error_formatter`. Output guardrails are debounced over accumulated transcript deltas; on trip the session forces `response.cancel` and sends a follow-up user message. Handoffs via `realtime_handoff(agent)`; `input_filter` unsupported. SIP via `OpenAIRealtimeSIPModel` + `build_initial_session_payload`.

## 2. Google: `@google/genai` live.connect and ADK run_live

`@google/genai` (live-guide, get-started-sdk, live-session, live-tools):

- `ai.live.connect({ model, config, callbacks: { onopen, onmessage, onerror, onclose } })` returns a session with `sendRealtimeInput({ audio | video | text | activityStart | activityEnd | audioStreamEnd })`, `sendClientContent({ turns, turnComplete })`, `sendToolResponse({ functionResponses })`, `close()`.
- `LiveServerMessage`: `setupComplete`, `serverContent` (`modelTurn.parts`, `interrupted`, `turnComplete`, `generationComplete`, `inputTranscription.text`, `outputTranscription.text`), `toolCall.functionCalls`, `toolCallCancellation.ids`, `goAway.timeLeft`, `sessionResumptionUpdate { newHandle, resumable }`, `usageMetadata`.
- Config: `responseModalities` (one of AUDIO or TEXT), `systemInstruction`, `speechConfig`, `inputAudioTranscription`, `outputAudioTranscription`, `tools`, `realtimeInputConfig.automaticActivityDetection { disabled, startOfSpeechSensitivity, endOfSpeechSensitivity, prefixPaddingMs, silenceDurationMs }`, `realtimeInputConfig.activityHandling: START_OF_ACTIVITY_INTERRUPTS | NO_INTERRUPTION`, `turnCoverage`, `contextWindowCompression { slidingWindow }`, `sessionResumption { handle }`, `proactivity`, `enableAffectiveDialog`.
- Interruption: server emits `serverContent.interrupted`; docs say "stop playing audio and clear queued playback". No truncate call exists; the model's own context is whatever it generated (docs do not promise alignment to what was heard). Pending tool calls are cancelled via `toolCallCancellation`.
- Tools: "the Live API doesn't support automatic tool response handling"; `behavior: NON_BLOCKING` + response `scheduling: INTERRUPT | WHEN_IDLE | SILENT`. Gemini 3.1 Flash Live: synchronous function calling only, Google Search yes, no code execution.
- Session: ~10 min WebSocket ceiling, 15 min audio-only / 2 min audio+video without compression; `goAway` precedes disconnect; resumption handles valid 2 h. Ephemeral tokens: `authTokens.create({ uses, expireTime, newSessionExpireTime, liveConnectConstraints })`, used as `apiKey` from the browser (v1alpha/v1beta only).

ADK (`adk.dev/live`, `live_request_queue.py`, `run_config.py`, `llm_response.py`):

- Input: `LiveRequestQueue` with `send_content(content, partial=)`, `send_realtime(blob)`, `send_activity_start()`, `send_activity_end()`, `send_audio_stream_end()`, `send(LiveRequest)`, `close()`. `LiveRequest` fields: `content`, `blob`, `activity_start`, `activity_end`, `audio_stream_end`, `close`, `partial`, `state_delta`. This is a direct precedent for the "one input union pushed into a queue" design.
- Loop: `runner.run_live(agent, queue, run_config)` is an async generator of `Event`.
- `RunConfig`: `response_modalities`, `streaming_mode: NONE | SSE | BIDI`, `speech_config`, `input_audio_transcription`, `output_audio_transcription`, `realtime_input_config`, `explicit_vad_signal`, `enable_affective_dialog`, `proactivity`, `session_resumption`, `context_window_compression`, `history_config`, `translation_config`, `avatar_config`, `save_live_blob`, `tool_thread_pool_config`, `max_llm_calls`, `support_cfc`.
- Output `Event` (inherits `LlmResponse`): `content`, `partial`, `turn_complete`, `turn_complete_reason`, `interaction_status`, `interrupted` ("Flag indicating that LLM was interrupted when generating content"), `input_transcription`, `output_transcription`, `voice_activity`, `go_away`, `live_session_resumption_update`, `usage_metadata`, `error_code`/`error_message`, plus `get_function_calls()` / `get_function_responses()`, `long_running_tool_ids`, `actions`.
- Tools execute automatically inside the runner (function_call event, then function_response event); long-running tools are tracked by id. Interruption is a flag on the event stream, not a control message; client must clear its own playback. Session resumption is automatic. Model support: Gemini Live only.

## 3. Vercel AI SDK (v7, 2026): yes, `experimental_realtime`

The premise "does it have anything bidirectional" is answered yes as of AI SDK 7:

- Provider spec `packages/provider/src/realtime-model/v4/`: `RealtimeModelV4` is a codec with `doCreateClientSecret`, `getWebSocketConfig({ token, url })`, `serializeClientEvent`, `parseServerEvent`, `buildSessionConfig`, optional `getHealthCheckResponse`. The SDK does not own the socket; the browser hook or the app does.
- Client events: `session-update`, `input-audio-append`, `input-audio-commit`, `input-audio-clear`, `conversation-item-create`, `conversation-item-truncate`, `response-create`, `response-cancel`.
- Server events: `session-created`, `session-updated`, `speech-started`, `speech-stopped`, `audio-committed`, `input-transcription-completed`, `conversation-item-added`, `response-created`, `output-item-added`, `content-part-added`, `text-delta`, `text-done`, `audio-delta`, `audio-transcript-delta`, `audio-transcript-done`, `audio-done`, `function-call-arguments-delta`, `function-call-arguments-done`, `content-part-done`, `output-item-done`, `response-done`, `error`, `custom`.
- Session config: `instructions`, `voice`, `outputModalities`, `inputAudioFormat`, `outputAudioFormat`, `inputAudioTranscription`, `outputAudioTranscription`, `turnDetection { type, threshold, prefixPaddingMs, silenceDurationMs }`, `tools`, `providerOptions`.
- Providers: OpenAI (`gpt-realtime`), Google (`gemini-3.1-flash-live-preview`), xAI (`grok-voice-latest`), AI Gateway. Gateway limits: 25 min session, 5 min idle, no image input, "Reconnecting does not resume a previous session."
- `experimental_useRealtime` (React): `connect/disconnect`, `startAudioCapture(stream)/stopAudioCapture`, `isCapturing`, `isPlaying`, `stopPlayback()`, `sendTextMessage`, `sendAudio(base64)`, `commitAudio`, `clearAudioBuffer`, `requestResponse({ modalities })`, `cancelResponse()`, `addToolOutput(callId, result)`, `messages`, `events`, `onToolCall`, `onEvent`. Tool calling is client-driven (`onToolCall` may return `undefined` and call `addToolOutput` later).
- The normalized vocabulary is visibly OpenAI-shaped (`conversation-item-truncate`, `input-audio-commit`); the Gemini provider must emulate or drop them. No `interrupted`/`truncated` server event and no activity-start/end client event exist in the union, so Gemini's native interruption and manual-VAD signals have no normalized home (UNVERIFIED how the Google provider maps `serverContent.interrupted`).

## 4. LiveKit Agents: `RealtimeModel` / `RealtimeSession` (the strongest prior art)

Abstract interface (`llm/realtime.py`, mirrored in `agents-js/agents/src/llm/realtime.ts`):

- `RealtimeCapabilities`: `message_truncation`, `turn_detection`, `user_transcription`, `auto_tool_reply_generation`, `audio_output`, `manual_function_calls`, `can_disable_turn_detection=False`, `supports_overlapping_speech=False`, `mutable_chat_context=False`, `mutable_instructions=False`, `mutable_tools=False`, `per_response_tool_choice=False`, `supports_say=False`. Node adds `midSessionChatCtxUpdate/InstructionsUpdate/ToolsUpdate` and deprecated `nativeTranscriptSync`.
- `RealtimeModel`: `capabilities`, `session(*, turn_detection_disabled)`, `aclose()`.
- `RealtimeSession` methods: `update_instructions(str)`, `update_chat_ctx(ChatContext)`, `update_tools(list[Tool])`, `update_options(tool_choice=)`, `push_audio(AudioFrame)`, `push_video(VideoFrame)`, `generate_reply(instructions=, tool_choice=, tools=) -> Future[GenerationCreatedEvent]`, `commit_audio()`, `clear_audio()`, `interrupt()`, `truncate(message_id=, modalities=, audio_end_ms=, audio_transcript=)`, `start_user_activity()`, `aclose()`.
- Events (Literal): `input_speech_started`, `input_speech_stopped { user_transcription_enabled }`, `input_audio_transcription_completed { item_id, transcript, is_final, confidence, turn_started_at }`, `generation_created { message_stream: AsyncIterable[MessageGeneration], function_stream: AsyncIterable[FunctionCall], user_initiated, response_id }`, `session_reconnected`, `metrics_collected`, `remote_item_added`, `error { type, timestamp, label, error, recoverable }`. `MessageGeneration = { message_id, text_stream, audio_stream, modalities: Awaitable[list["text"|"audio"]] }`. Note: no "interrupted" event; interruption is expressed as `input_speech_started` plus the streams closing.

Per-plugin mapping:

- OpenAI (`realtime_model.py`): capabilities `message_truncation=True, turn_detection=server_vad?, can_disable_turn_detection, user_transcription=input_audio_transcription is not None, auto_tool_reply_generation=False, manual_function_calls=True, mutable_chat_context=True, mutable_instructions=True, mutable_tools=True, per_response_tool_choice=True`. `speech_started/stopped` -> `input_speech_started/stopped`; transcription delta -> completed event with `is_final=False`; `response.created` -> `generation_created`; `response.done` -> `metrics_collected`. `truncate()` -> `conversation.item.truncate` (deletes the item if `audio_end_ms <= 0`); `interrupt()` -> `response.cancel`; `update_chat_ctx` diffs and sends `conversation.item.create/delete`; instructions/tools/options via `session.update`; reconnect replays session config + tools + chat ctx and emits `session_reconnected`. Options: `model, voice, tool_choice, input_audio_transcription, input_audio_noise_reduction, turn_detection, max_response_output_tokens, tracing, truncation, reasoning, modalities, speed, max_session_duration, azure fields`.
- Gemini (`realtime_api.py`): `message_truncation=False, auto_tool_reply_generation=True, manual_function_calls=False, mutable_tools=False, mutable_chat_context/instructions = not Gemini 3.1, per_response_tool_choice=False`. `interrupted` -> `input_speech_started` (only if no pending generation); `interrupt()` -> `start_user_activity()` (sends `activity_start`); `truncate()` -> warning no-op; `update_tools()` -> marks restart; voice/temperature change -> reconnect; `go_away` -> graceful restart; resumption handle stored and replayed. Options include `enable_affective_dialog, proactivity, realtime_input_config, context_window_compression, tool_behavior, tool_response_scheduling, thinking_config, image_encode_options, session_resumption`. Docs: Gemini 3.1 is incompatible with `generate_reply()`, `update_instructions()`, `update_chat_ctx()` and handoffs.
- Nova Sonic (`aws/experimental/realtime/realtime_model.py`): `message_truncation=False, turn_detection=True, user_transcription=True, auto_tool_reply_generation=True, manual_function_calls=False, per_response_tool_choice=False`. `interrupt()` and `truncate()` raise `NotImplementedError`; `update_options()` is a no-op; `textOutput SPECULATIVE` -> text stream, `FINAL` -> chat ctx; sessions recycled every ~6 min with 40-message / 1024-byte history caps; tool results go through a dedicated channel as contentStart/toolResult/contentEnd. Plugin-level `turn_detection: HIGH | MEDIUM | LOW`.
- Cross-plugin guidance (`models/realtime/`): "Realtime models don't provide interim transcription results"; no `say()` from text script; history loads as text only. Not unified: turn detection knobs (OpenAI `server_vad/semantic_vad {threshold, prefix_padding_ms, silence_duration_ms, eagerness, create_response, interrupt_response}` vs Gemini `automatic_activity_detection` sensitivities vs Nova `HIGH/MEDIUM/LOW`), truncation, tool-reply auto-generation, mutability, voice/temperature ranges, session limits.
- Who tracks played ms: the host, not the plugin. `agent_activity.py` waits for `audio_output.wait_for_playout()`, reads `playback_ev.playback_position` and `synchronized_transcript`, then `if msg_interrupted and self.llm.capabilities.message_truncation: self._rt_session.truncate(message_id=..., modalities=..., audio_end_ms=int(entry.out.playback_position * 1000), audio_transcript=forwarded_text)`. `_rt_session.interrupt()` is called on user audio activity and `start_user_activity()` on start of speech.

## 5. Pipecat: S2S services inside the frame pipeline

- Frames (`frames.py`): SystemFrames `InputAudioRawFrame`, `InputImageRawFrame`, `UserStartedSpeakingFrame`, `UserStoppedSpeakingFrame`, `BotStartedSpeakingFrame`, `BotStoppedSpeakingFrame`, `BotSpeakingFrame`, `InterruptionFrame` (replaces `StartInterruptionFrame`; `BotInterruptionFrame` replaced by `InterruptionTaskFrame`), `VADUserStartedSpeakingFrame`, `FunctionCallsStartedFrame`, `FunctionCallCancelFrame`, `CancelFrame`, `ErrorFrame`, `MetricsFrame`; DataFrames `TTSAudioRawFrame`, `OutputAudioRawFrame`, `TranscriptionFrame`, `InterimTranscriptionFrame`, `LLMTextFrame`, `TTSTextFrame`, `FunctionCallResultFrame`, `LLMMessagesUpdateFrame`, `LLMSetToolsFrame`; ControlFrames `LLMFullResponseStartFrame/EndFrame`, `TTSStartedFrame/StoppedFrame`, `FunctionCallInProgressFrame`, `LLMUpdateSettingsFrame`, `EndFrame`. New in 2026: `ProposedUserStartedSpeakingFrame` / `ProposedUserStoppedSpeakingFrame` (server-VAD proposals resolved by user-turn strategies).
- Pipecat's trick: an S2S service is just an `LLMService` that also emits `TTSAudioRawFrame` and `TranscriptionFrame`, so it slots where LLM+TTS would be; `LLMContextAggregatorPair` auto-detects `is_realtime_service=True` and decouples context writes from user-turn frames.
- `OpenAIRealtimeLLMService` (`openai/realtime/llm.py`): consumes `InputAudioRawFrame`, `InputImageRawFrame`, `LLMContextFrame`, `LLMUpdateSettingsFrame`, `InterruptionFrame`, `UserStarted/StoppedSpeakingFrame`; produces `TTSAudioRawFrame`, `InterimTranscriptionFrame`/`TranscriptionFrame`, `LLMFullResponseStartFrame`, function-call frames. `speech_started` -> `_truncate_current_audio_response()` + `ProposedUserStartedSpeakingFrame`. Truncation: `truncate_ms = min(elapsed_wall_clock_ms, audio_duration_ms_from_bytes)` then `conversation.item.truncate(audio_end_ms=truncate_ms)`; on failure it logs and continues. Turn detection: `TurnDetection` (server VAD), `SemanticTurnDetection`, or `False` with local VAD.
- `GeminiLiveLLMService`: docstring "Does NOT emit UserStartedSpeakingFrame / UserStoppedSpeakingFrame (the API exposes an `interrupted` event but no turn-start/-end)"; sends `activity_start`/`activity_end` when server VAD is disabled, with preroll so onset is not clipped; handles `session_resumption_update` and reconnects with the handle, else re-seeds context; video throttled to 1 fps; no truncation.
- `AWSNovaSonicLLMService`: same "does NOT emit user turn frames" docstring; `SPECULATIVE` vs `FINAL` text; older model needs an "assistant response trigger" wav; `session_continuation` helper rotates sessions around the ~8 min limit.
- Interruptions (`fundamentals/interruptions`): `InterruptionFrame` is a SystemFrame that cancels each processor's task and drops queued Data/Control frames; the output transport drains unplayed audio and pushes `TTSTextFrame`s in sync with playout so "text that never played never reaches the assistant context aggregator". For S2S: "the provider decides when the user barged in; Pipecat still flushes local audio output so the bot goes silent right away." Strategies: `VADUserTurnStartStrategy(enable_interruptions=)`, `MinWordsUserTurnStartStrategy`, mute strategies.

## 7. Other frameworks (one line each)

- Mastra: `MastraVoice` realtime implementations `OpenAIRealtimeVoice`, `GeminiLiveVoice`, `NovaSonicVoice`, `InworldRealtimeVoice`; methods `connect/send(stream)/speak/listen/addTools/updateConfig/close/on/off`; common events `speaking { audio: Int16Array }`, `writing { text, role }`, `error`, plus docs mention `turnComplete`, `usage`, `toolCall`, `interrupt`; provider-native events pass through under an `openAIRealtime:` prefix. - LangChain/LangGraph: no realtime abstraction; docs prescribe a "Sandwich" STT -> agent -> TTS pipeline of `RunnableGenerator`s with custom `VoiceAgentEvent`s (`stt_chunk`, `stt_output`, `agent_chunk`, `tts_chunk`); `react-voice-agent` and `voice-demo` repos delegate to OpenAI Realtime / LiveKit / ADK.
- Genkit: no Live/bidi abstraction found in genkit.dev model docs (grep for "live"/"bidirectional" returned nothing); Google routes Live to Firebase AI Logic client SDKs and ADK instead. UNVERIFIED beyond absence of evidence.
- Semantic Kernel (Python only, experimental): `RealtimeClientBase` with `create_session`, `update_session`, `delete_session`, `send`, `receive` (async generator) and events `RealtimeAudioEvent`, `RealtimeTextEvent`, `RealtimeFunctionCallEvent`, `RealtimeFunctionResultEvent`, generic `RealtimeEvent { event_type, service_type }`; implementations `OpenAIRealtimeWebsocket`, `OpenAIRealtimeWebRTC(audio_track=)`, `AzureRealtimeWebsocket/WebRTC`; `audio_output_callback` bypasses event parsing for latency. .NET and Java "coming soon".
- Spring AI: nothing; issue #1464 "Adding support for OpenAI's real-time model" open since 2024-10 with no implementation; only chunked `StreamingSpeechModel` TTS exists.

Recommendation for effect-uai:

- Common `RealtimeInput` (queue): `AudioFrame`, `VideoFrame` (marker-gated), `Text`, `ToolResult`, `GenerateReply`, `Interrupt`, and optional `ActivityStart`/`ActivityEnd`/`CommitAudio` whose adapters either map or `warnDropped`. Follow ADK's `LiveRequest` and LiveKit's method list; both converged independently on this set.
- Common `RealtimeEvent` (stream): `AudioDelta`, `OutputTranscriptDelta`, `InputTranscript { text, final }`, `SpeechStarted`, `SpeechStopped`, `ResponseStarted`, `ResponseDone { usage }`, `ToolCall`, `ToolCallCancelled`, `Interrupted { itemId? }`, `UsageUpdate`, `SessionEnding`, `Reconnected`, `Error`. Reuse `Turn.ts` names where semantics match.
- Capability flags, LiveKit style, but as phantom markers in the house style: `RealtimeTruncation` (O only), `RealtimeManualTurn` (O `none` mode, G `disabled` VAD; not N), `RealtimeVideoInput` (O, G), `RealtimeMutableSession` (O; G partial), `RealtimeTextOnlyOutput` (O, G; not N1). Everything LiveKit lists as `mutable_*`, `per_response_tool_choice`, `auto_tool_reply_generation` proves those are not unifiable.
- Keep provider-typed: turn-detection config (three incompatible shapes), voice/temperature ranges, tool `behavior`/`scheduling` (G), `truncation`/`reasoning`/`noise_reduction` (O), `proactivity`/`affectiveDialog`/`contextWindowCompression`/`sessionResumption` (G), `turn_detection HIGH/MEDIUM/LOW` and session continuation (N), transports (WebRTC/SIP are OpenAI-only concerns).
- Playback truncation: every SDK puts played-ms tracking outside the provider adapter. OpenAI Agents JS approximates with wall clock since first delta (`_firstAudioTimestamp`) clamped to bytes sent; Pipecat does `min(elapsed, bytes-derived duration)`; LiveKit reads the real playout position from the audio sink and calls `truncate(audio_end_ms=playback_position*1000)` only when `message_truncation` is set; Twilio transport uses `mark` acks. For effect-uai: the session should accept an optional `Truncate { itemId, audioEndMs }` input (OpenAI adapter only, marker-gated) and ship a helper that derives audioEndMs from bytes emitted + first-delta timestamp for callers without a real player clock; default behaviour on `Interrupted` is "stop and drop queued audio", which is all G and N can do.

## 9. Config mutability, reconnect, backpressure, browser split

- Mid-session config: OpenAI `session.update` covers instructions/tools/turn detection/modalities (voice locked after first audio). Gemini: instructions can be sent as client content on non-3.1 models; tool changes force reconnect (LiveKit `update_tools` -> restart); 3.1 rejects `update_instructions`/`update_chat_ctx`. Nova: `update_options` is a no-op. LiveKit encodes this as `mutable_*` flags; OpenAI Agents SDK assumes OpenAI; Vercel exposes `session-update` and lets non-OpenAI providers ignore fields.
- Reconnect/resumption: Gemini has first-class `sessionResumption` handles + `goAway`; LiveKit Gemini plugin stores `new_handle` and replays only post-handle context; Pipecat reconnects with the handle or re-seeds context. OpenAI: no resumption; LiveKit replays session config + tools + chat ctx and emits `session_reconnected` after exponential backoff; Vercel Gateway says reconnect starts a new session. Nova: LiveKit recycles every ~6 min waiting for `END_TURN`; Pipecat `session_continuation` buffers audio across the swap. ADK: "automatic session resumption".
- Backpressure on audio input: none of the SDKs apply it. LiveKit `push_audio` is fire-and-forget into a channel; Pipecat drops nothing but relies on transport pacing; ADK's `LiveRequestQueue` is an unbounded asyncio queue; OpenAI Agents JS `sendAudio` writes straight to the socket; Nova docs require real-time cadence (~32 ms frames). Gemini docs say audio must be paced; OpenAI caps 15 MB per append. For effect-uai an unbounded or sliding `Queue<RealtimeInput>` mirrors prior art; a bounded queue with `Queue.offer` drop policy would be novel and should be opt-in.
- Browser vs server: OpenAI ephemeral `client_secrets` (Agents JS WebRTC default in browser, WebSocket in Node); Gemini `authTokens.create` ephemeral tokens with `liveConnectConstraints`, browser uses the token as `apiKey` (client-to-server) or goes server-to-server; Vercel `getToken` route + `useRealtime` in the browser, `getWebSocketConfig` codec in Node; LiveKit and Pipecat are server-only (browser reaches them over WebRTC rooms / RTVI); Nova has no browser story (SigV4 only). effect-uai's session should be transport-agnostic (bytes in, bytes out) and leave WebRTC to a browser-side recipe; ephemeral-token minting is a provider-typed helper, not part of the session.
